## 실제 소스에서 확인한 문제

휴대폰에서 PDF/AI 설명/확인문제를 하나의 패널씩 보여주는 구조인데, 원래 `sourcePage()`와 `open-quiz`가 **반대편 패널의 콘텐츠만 변경**했습니다. 이 두 작업은 휴대폰에서 활성화된 탭을 변경하지 않아 사용자는 버튼을 누르고도 결과를 바로 볼 수 없었습니다.

## 이번 수정 (단일 UX 결함)

- `revealPhoneSide(side)`: 현재 뷰포트가 최대 670px인 경우에만 `setPhoneSide(side)`를 호출합니다.
- AI 설명의 PDF 출처 열기: 반대편 패널을 PDF로 바꾼 후 휴대폰에서 그 화면을 표시합니다.
- AI 설명의 확인문제 풀기: 반대편 패널을 문제로 바꾼 후 휴대폰에서 그 화면을 표시합니다.
- **보존:** Dark Workspace v1.2 CSS 전체, 671px 이상의 태블릿 분할 레이아웃, 기존 문항 내용·채점 방식·PDF 로컬 URL 처리·분할 비율·버튼 문구.

## 다음 브라우저 QA 시나리오

1. `python -m http.server 8000`으로 루트에서만 로컬 실행. 합성 PDF와 예시 문항만 사용합니다.
2. 폭 320px, 390px: 한쪽 화면을 AI 설명으로 선택하고 **확인문제 풀기**를 누르면 반대편 패널의 문제 목록이 바로 표시되는지, 하단 활성 탭도 맞는지 확인합니다.
3. 폭 320px, 390px: AI 설명에서 **PDF 12쪽 열기**를 누르면 PDF 화면으로 전환되며 12쪽 표시가 유지되는지 확인합니다.
4. 폭 320px, 390px: 좌·우 구성을 바꾼 역방향에서도 2, 3을 반복합니다.
5. 폭 768px 세로, 1024px 가로, 1366px 가로: 위 두 조작 후 두 패널이 계속 함께 보이는지, 크기 조절이 유지되는지 확인합니다.
6. 키보드 탭 탐색, 초점 표시, `prefers-reduced-motion`, 문항별 즉시 해설, 로컬 PDF 미리보기, 화면 회전 전환을 회귀 확인합니다.
7. 네트워크 탭에서 서버 업로드 및 제3자 API 요청 없음 확인; 화면 스크린샷과 결과를 최신 PR HEAD SHA에 기록합니다.
