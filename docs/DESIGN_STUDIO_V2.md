## 의도
학습의 주인공은 PDF 본문이고, 앱은 그 옆에서 원문·설명·문제를 오가는 **읽기 작업대**입니다. 기존 다크 UI CSS와 시각 장식 코드를 그대로 리스킨하지 않고, 냉정한 기술 문서/실험 노트의 편집 감각으로 새 CSS를 작성합니다. 대형 히어로, 챗봇 그라데이션, 똑같은 카드 더미, 장식적 아이콘은 사용하지 않습니다.

## 디자인 토큰 (프로젝트 고유)
| 역할 | 색상 | 선택 이유 |
| --- | --- | --- |
| Heading ink / masthead | `#172932` | 공학 노트의 검은 잉크에 가까운 안정된 헤더 |
| Canvas | `#e8edf0` | 실제 PDF 백지를 돋보이게 하는 차가운 작업대 |
| Paper | `#ffffff` | PDF와 설명의 원본 가독성 |
| Body ink | `#20313a` | 작은 한국어 본문의 차분한 대비 |
| Copper-green accent | `#146e71` | 명확한 인터랙션을 위한 절제된 편집 포인트 |
| Hairline | `#cad5d9` | 분할선과 정보 경계, 다크 카드 중첩을 대신 |

- **타이포그래피:** 로컬 폰트 우선 `Pretendard` → `Apple SD Gothic Neo` → `Noto Sans KR` → 시스템 산세리프. 수식에는 로컬 Georgia/Cambria. 외부 폰트 로딩 없음.
- **정보 크기:** 헤더 64px 내외, 화면 전환 50px 내외, 설명 제목 32~44px, 본문 14~15px. 보조 정보는 지나치게 작지 않도록 11~12px.
- **레이아웃:**
```text
[ FOLIO                       강의 제목 / 진도 ]
[ 좌측 보기: PDF ] ┃ [ 우측 보기: AI 설명      ]
[         원본 문서 ]┃ [ 근거 중심 편집 텍스트   ]
[          ...      ]┃ [ 핵심 개념, 식, 예제     ]
[  페이지  줌       ]┃ [ PDF 12쪽 / 확인문제    ]

세로 태블릿: 같은 두 패널을 상하로 분할
휴대폰: 현재 패널만 표시하고 하단에 [왼쪽 화면 / 오른쪽 화면]
```
- **기능 보존:** 좌·우 독립 PDF/설명/문제 전환, 30~70% 분할 및 키보드 이동, 세로/가로 적응, 모바일 자동 탭 전환, 로컬 PDF 파일 미리보기, 각 문항 채점/해설.
- **PDF 기본 보기:** 원본 문서 색상을 우선하고 선택 가능한 반전 보기만 유지. PDF 데이터를 전송하거나 실제 AI 분석을 생성하지 않음.

## 과도한 템플릿 패턴 검토
처음 고려한 '따뜻한 크림 + 세리프 + 주황색' 조합은 일반적인 AI 디자인 템플릿에 가까워 제외했습니다. 어두운 배경+네온 버튼 역시 기존 Workspace와 차별이 약합니다. 대신 **차가운 종이 작업대 + 짙은 잉크 + 청록색 편집 포인트**를 선택합니다. 브랜드 이미지나 외부 이미지 의존 없이 실제 강의 텍스트 자체가 화면의 중심에 옵니다.

## 확대·축소 / 모바일 가독성 후속 점검 (2026-11-12)
- **실제 확인한 결함:** 기존 `pdfZoom()`은 줌 클릭마다 `renderPdf()`로 뷰어 DOM 전체를 재생성하여 시연용 PDF의 세로 스크롤 위치를 초기화했습니다. 또한 PDF 영역의 `justify-content:center`가 확대 문서의 왼쪽 경계를 가로 스크롤로 접근하기 어렵게 할 가능성이 있었습니다.
- **변경:** PDF 영역을 스크롤 시작점 기준 왼쪽 정렬하되 내부 문서는 기존처럼 가운데 배치. 시연용 PDF는 확대 시 기존 DOM을 유지하고 현재 스크롤 위치에 줌 배율을 반영. `맞춤 보기`도 동일한 갱신 경로로 연결. 로컬 PDF는 기존 `blob:` 및 `#page=&zoom=` 방식으로 iframe **노드는 유지**하나 브라우저 내장 PDF 뷰어의 내부 스크롤 유지는 보장하지 않습니다.
- **검증 추가:** 768×1024 태블릿의 PDF 읽던 위치/DOM 보존, 320·390px 휴대폰 160% 확대 후 문서 좌우 접근성, 로컬 PDF iframe의 URL 및 노드 보존. Chromium/WebKit 각 16개 회귀, 기존 브라우저 캡처 4장에 줌 130% 태블릿·160% 휴대폰 사진 2장 추가. 정확한 HEAD와 CI 성공 여부는 Actions의 실제 로그로 별도 확인합니다.
